### Static NAT Review

* **Static NAT** involves statically configuring one-to-one mappings of private IP addresses to public IP addresses.
* When traffic from the internal host is sent to the outside network, the router will translate the source address.
  ![Pasted image 20260722050324.png](../_assets/Pasted%20image%2020260722050324.png)
* However, this one-to-one mapping also allows external hosts to access the internal host via the inside global address.
  ![Pasted image 20260722050427.png](../_assets/Pasted%20image%2020260722050427.png)

---

### Dynamic NAT

* In **dynamic NAT**, the router dynamically maps *inside local* addresses to *inside global* addresses as needed.

* An ACL is used to identify which traffic should be translated. We know that ACL is used to configure which traffic will be forwarded and which traffic will be blocked. ==But ACL can also be used to identify traffic, and this time we will not apply it on interface using **`ip access-group`** command.==
  - If the source IP is **permitted** by the ACL, the source IP will be translated.
  - If the source IP is **denied** by the ACL, the source IP will NOT be translated. \*==the traffic will NOT be dropped!==

* A NAT pool is used to define the available *inside global* addresses.
  ![ 400](../_assets/Pasted%20image%2020260722051345.png)
  ![Pasted image 20260722051429.png](../_assets/Pasted%20image%2020260722051429.png)
  
  **NOTE:** ==If the source IP is not permitted in the ACL for dynamic NAT. It doesn't mean the packet will be dropped. It just won't be translated to an *inside global* IP address.==

* If there aren't enough *inside global* IP addresses available (=all are currently being used), it is called **NAT pool exhaustion**.
  - If a packet from another inside host arrives and needs NAT but there are no available addresses, the router will drop the packet.
  - The host will be unable to access outside networks until one of the *inside global* IP addresses becomes available.
  - Dynamic NAT entries will time out automatically if not used, or you can clear them manually.

### Dynamic NAT Configuration

![Pasted image 20260722052748.png](../_assets/Pasted%20image%2020260722052748.png)

* In `ip nat pool...` command, the prefix length is used to check whether the IP address range (`100.0.0.0` to `100.0.0.255`) is valid. If it is invalid, the command will be rejected.
* In `ip nat inside source list 1 pool POOL1`, `list 1` means to use access list 1 (ACL number of 1) and `pool POOL1` means to use the NAT pool POOL1.

To demonstrate, we sent some traffic from PC1 and PC2 to `8.8.8.8`. Let's check R1's translation table.

![Pasted image 20260722053424.png](../_assets/Pasted%20image%2020260722053424.png)

* Along with the original mapping, there are also dynamic entries for different protocols if those protocols are used. In this case, separate entries for UDP and ICMP entries for the address `192.168.0.167` and `192.168.0.168` are made. For reference, this format in the NAT translation table is the original.
  ![Pasted image 20260722053738.png](../_assets/Pasted%20image%2020260722053738.png)
* After about a minute, those UDP and ICMP entries will be cleared. The default original dynamic mapping themselves have a default timeout value of **24 hours**. Each time a translation is made, the timer resets.
* ==Since the original mappings are also dynamically made, if you use the command **`clear ip nat translation *`**, they will also be cleared!==

Here is the result of `show ip nat statistics` command:

![Pasted image 20260722054207.png](../_assets/Pasted%20image%2020260722054207.png)

* All translations are dynamically made since we configured a dynamic NAT by mapping the ACL to the pool. There are total of 6 dynamic entries in the above example.
* For additional note, ==**Extended entries** are those UDP and ICMP entries that are cleared after a minute==.
* You can confirm the dynamic mapping from ACL 1 to POOL 1 in this section of the `show ip nat statistics` command.

### PAT (NAT Overload)

![Pasted image 20260722060337.png](../_assets/Pasted%20image%2020260722060337.png)

* **PAT** (aka **NAT overload**) translates both the IP address and the port number (if necessary).
  - If both hosts have chosen different random port numbers, PAT will keep those ports after the translation
  - If both hosts have chosen the same random port number, PAT will use a different port for the other host so they will can be distinguished.

* By using a unique port number of each communication flow, ==a single public IP address can be used by many different internal hosts (port number are 16 bits = over 65,000 available port numbers).==

* The router will keep track of which *inside local* address is using which *inside global* address and port.

* **PAT is very useful in preserving public IP addresses, and is used by many networks all over the world.**

---

### PAT Configuration (Pool)

![Pasted image 20260722060612.png](../_assets/Pasted%20image%2020260722060612.png)

* We don't have to use a very large public IP range using PAT. In fact, you only need one public IP address for most cases. We just defined the range `100.0.0.0 100.0.0.3` to have some room for growth (scalability).

* As long as the public IP range fits available range based on the specified subnet, the configured command for `ip nat pool` will be accepted even if you don't include all the IP address available in the prefix length.

* `100.0.0.0` to `100.0.0.3` all fits in the subnet `100.0.0.0/24`. This means the `ip nat pool POOL1 100.0.0.0 100.0.0.3 prefix-length 24` is a valid command!

* To configure PAT, the list of commands is almost the same when configuring standard dynamic NAT. You just have to add the **`overload`** keyword at the end of `ip nat inside source list...` command.
