### Simple Network Management Protocol

* SNMP is an industry-standard framework and protocol that was originally released in 1988. Below are list of RFCs for **SNMPv1** (there are multiple SNMP versions):
  - RFC 1065 - Structure and identification of management information for TCP/IP-based internets
  - RFC 1066 - Management information base for network management of TCP/IP-based internets
  - RFC 1067 - A simple network management protocol
* Don't let the 'Simple' in the name fool you! SNMP is a fairly complex topic, especially SNMPv3. Luckily, in the CCNA, you only have to understand the fundamentals/basics.
* SNMP can be used to monitor the status of devices, make configuration changes, etc.
* There are two main types of devices in SNMP:
  1. Managed Devices
     - These are the devices being managed using SNMP.
     - For example, network devices like routers and switches.
  1. Network Management Station (NMS)
     - The device(s) managing the managed devices.
     - This is the SNMP 'server'.

### SNMP Components

![Pasted image 20260714055456.png](../_assets/Pasted%20image%2020260714055456.png)

**NMS (SRV1)**

![ 300](../_assets/Pasted%20image%2020260714055710.png)

* The **SNMP Manager** is the software on the NMS that interacts with the managed devices.
  - It receives notifications, sends requests for information, sends configuration changes, etc.
* The **SNMP Application** provides an interface for the network admin to interact with.
  - Displays alerts, statistics, charts, etc.
  - **SolarWinds** is an example of SNMP Application
  ![Pasted image 20260714055928.png](../_assets/Pasted%20image%2020260714055928.png)

**Managed Devices**

![Pasted image 20260714060134.png](../_assets/Pasted%20image%2020260714060134.png)

* The **SNMP Agent** is the SNMP software running on the managed devices that interacts with the SNMP Manager on the NMS.
  - It sends notifications to/receives messages from the NMS.
* The **Management Information Base (MIB)** is the structure that contains the variables that are managed by SNMP.
  - Each variable is identified with an Object ID (OID)
  - Example variables: Interface status, traffic throughput, CPU usage, temperature, etc.

### SNMP Versions

* Many versions of SNMP have been proposed/developed, however only three major versions have achieved wide-spread use:
* **SNMPv1**
  - The original version of SNMP.
* **SNMPv2c**
  - Allows the NMS to retrieve large amounts of information in a single request, so it is more efficient.
  - 'c' refers to the 'community strings' used as passwords in SNMPv1, removed from SNMPv2, and then added back for SNMPv2c.
* **SNMPv3**
  - A much more secure version of SNMP that supports strong **encryption** and **authentication**. Whenever possible, this version should be used!

### SNMP 'Read' Messages

* **Get**
  - A request sent from the manager to the agent to retrieve the value of a variable (OID), or multiple variables. The agent will send a *Response* message with the current value of each variable.
  ![Pasted image 20260715051033.png](../_assets/Pasted%20image%2020260715051033.png)
* **GetNext**
  - A request sent from the manager to the agent to discover the available variables in the MIB.
* **GetBulk**
  - A more efficient version of the **GetNext** message (introduced in SNMPv2).

---

### SNMP 'Write' Messages

* **Set**
  - A request sent from the manager to the agent to change the value of one ore more variables. The agent will send a *Response* message with the new values.
  ![Pasted image 20260715051232.png](../_assets/Pasted%20image%2020260715051232.png)

---

### SNMP 'Notification' Messages

* **Trap**
  - A notification sent from the agent to the manager. The manager does not send a Response message to acknowledge that it received the Trap, so these messages are 'unreliable'. Also, SNMP uses UDP, so there are no 're-transmissions'.
  ![Pasted image 20260715052046.png](../_assets/Pasted%20image%2020260715052046.png)
* **Inform**
  - A notification message that is acknowledged with a Response message. Even though SNMP is sent with UDP, there is a notification message with 'reliability' built in itself, meaning a Response message will be sent as an acknowledgement.
  - Originally used for communications between managers, but later updates allow agents to send Inform messages to managers, too.

---

### SNMP 'Response' Messages

* **Response**
  - Response messages are already demonstrated in the example above.
  - Basically, it is sent by either a manager or agent as a form of acknowledgement that it received an SNMP message (get, set, inform, etc.).
  - Response messages will not be send if an agent sends a **trap** messages.

**SNMP port numbers review:**
- SNMP 'Agent' = **UDP 161**
- SNMP 'Manager' = **UDP 162**

### SNMPv2c Configuration

![Pasted image 20260715054057.png](../_assets/Pasted%20image%2020260715054057.png)

* For SNMP *community strings*, the default strings are:
  - ro = **public**
  - rw = **private**
* Since we used 'read-only' SNMP community strings, the NMS cannot send *Set* messages to configure R1.
* **`snmp-server enable traps snmp linkdown linkup`** = `linkdown linukp` means to send *Trap* messages whenever one of R1's interfaces goes up or down.
* **`snmp-server enable traps config`** = send *Trap* messages whenever R1's configuration have been updated/changed.

### SNMP Summary

* SNMP helps manage devices over a network.
* **Managed Devices** are the devices being managed using SNMP, such as network devices (routers, switches, firewalls)
* **Network Management Stations (NMS)** are the SNMP 'servers' that manage the devices.
  - NMS receives notifications from managed devices
  - NMS changes settings on managed devices
  - NMS checks status of managed devices
* Variables such as interface status, temperature, traffic load, host name, etc. are stored in the Management Information Base (MIB) and identified using Object IDs (OIDs)
* Main SNMP version: SNMPv1, SNMPv2c, SNMPv3
* SNMP messages: Get, GetNext, GetBulk, Set, Trap, Inform, Response
