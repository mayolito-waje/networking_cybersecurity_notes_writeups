### RIP Intro

* **Routing Information Protocol** (industry standard)
* Distance vector IGP (uses routing-by-ruor logic to learn/share routes)
* RIP uses hop count as its metric. One router means one hop. The interface bandwidth is **irrelevant**.
* The maximum hop count is **15**. Anything more than that is considered *unreachable*. This makes RIP not ideal for enterprise networks.
* RIP has three versions: **RIPv1** (used for IPv4), **RIPv2** (used for IPv4), and **RIPng** (RIP Next Generation, used for IPv6).
* RIP uses two message types:
  **Request:** To ask RIP-enabled neighbor routers to send their routing table.
  **Response:** To send the local router's routing table to neighboring routers.
* By default, RIP-enabled routers will share their routing table *every **30 seconds***.

---

### RIPv1 and RIPv2

**RIPv1**

* only advertises *classful* addresses (Class A, Class B, Class C)
* doesn't support VLSM, CIDR
* doesn't include subnet mask information in advertisements (Response messages)
  `10.1.1.0/24` will become `10.0.0.0` (Class A address, so assumed `/8`)
  `172.16.192.0/18` will become `172.16.0.0` (Class B address, so assumed `/16`)
  `192.168.1.4/30` will become `192.168.1.0` (Class C address, so assumed to be `/24`)
* messages are **broadcast** to `255.255.255.255`

**RIPv2**

* supports VLSM, CIDR
* includes subnet mask information in advertisements
* messages are **multicast** to `224.0.0.9`

**Broadcast** messages are delivered to all devices on the local network.
**Multicast** messages are delivered only to devices that have joined that specific *multicast group*.

### RIP Configuration

![ 300](../_assets/Pasted%20image%2020260611060309.png)

![ 500](../_assets/Pasted%20image%2020260611060500.png)

* `R1(config)# router rip` - enters **RIP configuration** mode. The mode will now be in `(config-router)` instead of `(config)`.
* `R1(config-router)# version 2` - enable to use **RIPv2**. No one uses classful addresses anymore.
* `R1(config-router)# no auto-summary` - **on** by default. `auto-summary` advertises IP addresses as **classful addresses**. So `172.16.192.0/18` will become `172.16.0.0` (Class B address, so assumed `/16`). So make sure to disable it!

Let's talk about the `network` command first:

* The RIP `network` command is **classful**, so it will automatically convert addresses to classful networks.
* For example, even if you enter the command `network 10.0.12.0`, it will be converted to `network 10.0.0.0` (a class A network).
* There is no need to enter the network mask.

---

### `network` Command

* The `network` command tells the router to:
  * look for interfaces with an IP address that is in the specified range
  * then it will activate RIP on the interfaces that fill in the range
  * it will form adjacencies with connected RIP neighbors
  * advertise **the network prefix of the interface** (NOT the prefix in the `network` command)
* The OSPF and EIGRP `network` actually works in the *same way*!

![ 500](../_assets/Pasted%20image%2020260611061825.png)

* Because the `network` command is classful, `10.0.0.0` is assumed to be `10.0.0.0/8`
* R1 will look for any interfaces with an IP address that matches `10.0.0.0/8`. Because it is `/8`, it only needs to match the first 8 bits.
* `10.0.12.1` and `10.0.13.1` both match, so RIP will activate on `G0/0` and `G1/0`.
* R1 forms adjacencies with its neighbors R2 and R3.
* R1 advertises `10.0.12.0/30` and `10.0.13.0/30` to its RIP neighbors. Not that **it won't advertise the network of `10.0.0.0/8`**!
* The `network` command doesn't tell the router which networks to advertise. It tells the router which interfaces to activate RIP on, and then the router will *advertise the network prefix of those interfaces*.

![ 500](../_assets/Pasted%20image%2020260611062313.png)

* Because the `network` command is classful, `172.16.0.0` is assumed to be `172.16.0.0/16`.
* R1 will look for any interfaces with an IP address that matches `172.16.0.0/16`. `172.16.1.14` matches, so R1 will activate RIP on `G2/0`.
* There are no RIP neighbors connected to `G2/0`, so no adjacencies are formed.
* R1 advertises `172.16.1.0/28` (NOT \`172.16.0.0/16) to its RIP neighbors.
* Although there are no RIP neighbors connected to `G2/0`, R1 will continuously send RIP advertisements out of `G2/0`. This is unnecessary traffic, so `G2/0` should be configured as a **passive interface**.

---

### `passive-interface` Command

![ 300](../_assets/Pasted%20image%2020260611062730.png)

![ 500](../_assets/Pasted%20image%2020260611062819.png)

* The `passive-interface` command tells the router to stop sending RIP advertisements out of the specified interface (`G2/0`).
* However, the router will continue to advertise the network prefix of the interface (`172.16.1.0/28`) to its RIP neighbors (R2 and R3).
* You should always use this command on interfaces which don't have any RIP neighbors.
* EIGRP and OSPF both have the same passive interface functionality, using the same command.

### `show ip protocols`

![ 500](../_assets/Pasted%20image%2020260612212114.png)

`show ip protocols` is a useful command and can be used to RIP, EIGRP, and OSPF to check various stats.

* The information shows that the dynamic routing protocol used is RIP.
* The default version control is 2 which means it uses RIPv2.
* Since we used the command `no auto summary`, the automatic network summarization is not in effect.
* `Maximum path: 4` means that the maximum paths RIP can use to reach the same destination using load-balancing is 4 (which is the default value). Note that the case only applies to paths with the **same metrics**. However, you can change it using the command while in RIP config mode: `maximum-paths ?` where ? is the number of paths (max value of **32**). The command also applies to EIGRP and OSPF.
* `Routing for Networks` is the list of interfaces to active RIP on. Note that the addresses in this value is not what is actually advertised and will actually advertise the interface's actual prefix length.
* You can also see the configured passive interface (`G2/0`)
* `Routing Information Sources` shows the RIP neighbors, which is `10.0.12.2` (R2)  and `10.0.13.2` (R3).
* The `Distance` is the administrative distance (AD) of RIP, which defaults to 120. You can actually change the AD of the protocol using the command: `distance ?` where ? is the AD value. This is useful when you want to prioritize a routing protocol over the the others. The command is also applicable to EIGRP and OSPF.

### EIGRP Intro

* EIGRP means **Enhanced Interior Gateway Routing Protocol**
* EIGRP was Cisco proprietary, but Cisco has now published it openly so other vendors can implement it on their equipment.
* Considered an advanced/hybrid distance vector routing protocol.
* Much faster than RIP in reacting to changes in the network.
* Does not have the 15 hop count limit of RIP.
* Sends messages using multicast address of **224.0.0.10**.
* Is the only IGP that can perform **unequal**-cost load-balancing (by default it performs ECMP load-balancing over 4 paths like RIP).

### EIGRP Configuration

![ 300](../_assets/Pasted%20image%2020260613155115.png)

![ 500](../_assets/Pasted%20image%2020260613155138.png)

* `router eigrp 1` set EIGRP on the router with AS number of 1. The AS (Autonomous System) number must match between routers, or they will not form an adjacency and share route information.
* Auto-summary might be enabled or disabled by default, depending on the router/IOS version. If it's enabled, disable it.
* The **network** command will assume a classful address if you don't specify the mask.
* EIGRP uses a *wildcard* mask instead of a regular subnet mask.

### `show ip protocols` (EIGRP)

![ 500](../_assets/Pasted%20image%2020260613161144.png)

* EIGRP metric uses interface bandwidth and delay by default. Look at `Metric weight`, `K1` and `K3` values are set to **1**, which are interface bandwidth and the delay respectively. The bandwidth of the slowest link in the path plus the sum of the delay values of all the link in the path are used to calculate the metric. `K2`, `K4`, and `K5` are set to **0** by default, and is not used to calculate the metric (though you can configure them to adjust the calculation).

### EIGRP Router ID

![ 500](../_assets/Pasted%20image%2020260613165220.png)

* In EIGRP and OSPF, the router has a unique ID, which identifies it within the AS.
* In R1, the router ID is `172.16.1.14`. The router ID is determined with the following priority:
  1. Manual configuration
  1. Highest IP address on a loopback interface
  1. Highest IP address on a physical interface (in this case, R1's `G2/0`'s IP address became the router ID, which is `172.16.1.14`!)
* The Router ID is a 32 bit value. However, it is **not** an actual IP address, but rather configured with a dotted decimal format.

![ 500](../_assets/Pasted%20image%2020260613165758.png)
![ 500](../_assets/Pasted%20image%2020260613165814.png)

* To manually configure the Router ID, use the command `eigrp router-id ?` where ? is the Router ID value.
* In this case, we set the Router ID to `1.1.1.1`. Since manual configuration takes the most priority in Router ID configuration, `1.1.1.1` became R1's Router ID.
