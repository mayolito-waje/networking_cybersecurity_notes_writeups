### Loopback Interfaces

![ 250](../_assets/Pasted%20image%2020260621140705.png)

* A loopback interface is a virtual interface in the router.
* It is always up/up (unless you manually shut it down)
* It is not dependent on a physical interface.
* So, it provides a consistent IP address that can be used to reach/identify the router.

![ 250](../_assets/Pasted%20image%2020260621141027.png)

For example, even if the physical interface in R1 gets shut down due to some physical issues, routers can still reach R1 because its loopback interface is always in up/up mode.

### OSPF Network Types

The OSPF **network type** refers to the type of connection between OSPF neighbors (Ethernet, etc). There area three main OSPF network types:

* **Broadcast** - enabled by default on **Ethernet** and **FDDI** (Fiber Distributed Data Interfaces) interfaces
* **Point-to-point** - enabled by default on **PPP** (Point-to-Point Protocol) and **HDLC** (High-Level Data Link Control) interfaces
* **Non-broadcast** - enabled by default on **Frame Relay** and **X.25** interfaces

In CCNA, we will focus mainly on configuring **Broadcast** and **Point-to-point** network types.

### OSPF Broadcast Network Type

![Pasted image 20260621141901.png](../_assets/Pasted%20image%2020260621141901.png)

* So far, we have been using broadcast network type, since we uses Gigabit Ethernet interfaces.
* Broadcast network type is enabled on **Ethernet** and **FDDI** interfaces by default.
* Routers *dynamically discover* neighbors by sending/listening for OSPF Hello messages using multicast address `224.0.0.5`.
* A **DR** (designated router) and **BDR** (backup designated router) must be elected on each subnet (only DR if there are no OSPF neighbors, ie. R1's G1/0 interface).
* Routers which aren't the DR or BDR become a **DROther**.

### Broadcast - OSPF Priority

![ 250](../_assets/Pasted%20image%2020260621143415.png)

* To change the OSPF priority of an interface, use the command `ip ospf priority *value*`.
* We set R2's G0/0 OSPF Priority to max value (255).
* A key note to remember, If you set the OSPF interface priority to **0**, the router **CANNOT** be the DR/BDR for the subnet **NO MATTER WHAT**.

Now let's look if R2's G0/0 interface becomes the DR:

![Pasted image 20260621143746.png](../_assets/Pasted%20image%2020260621143746.png)

That's strange! It should be the DR now that the OSPF priority is set to 255. Why?

* **The DR/BDR election is 'non-preemptive'. Once the DR/BDR are selected they will keep their role until OSPF is reset, the interface fails/is shut down, etc.**

Although it is bad idea to do on a live network, let's reset the OSPF router on R5 to see if the role changes:

![Pasted image 20260621144051.png](../_assets/Pasted%20image%2020260621144051.png)

Now you can see that the OSPF neighbors of R5 went down.

![Pasted image 20260621144135.png](../_assets/Pasted%20image%2020260621144135.png)

Then, R2 and R4 returns to the full state, but not R3. Why? We will learn about this later.

![Pasted image 20260621145052.png](../_assets/Pasted%20image%2020260621145052.png)

![Pasted image 20260621144234.png](../_assets/Pasted%20image%2020260621144234.png)

There are two points we can learn from OSPF by analyzing the highlighted section:

* **R4 became the DR, not R2. R2 became the BDR.**
  * When the DR goes down, the BDR becomes the new DR (R4, is previously a BDR, so it now becomes the new DR after the previous DR shuts down!). Then an election is held for the next BDR. Since R2 has the highest OSPF Priority, it becomes the BDR.
* **R3 is a DROther, and is stable in the 2-way state.** R5 is also a DROther.
  * DROthers (R3 and R5 in this subnet) will only move to the FULL state with the DR and BDR. The neighbor state with other DROthers will be 2-way.

So now we learned that the BDR becomes the DR if the previous DR shuts down even though the BDR doesn't have the highest OSPF priority. We also learned the DROthers don't perform full form adjacency with other DROthers and will always enter 2-way state.

![Pasted image 20260621145806.png](../_assets/Pasted%20image%2020260621145806.png)

* In the broadcast network type, routers will only form a full OSPF adjacency with the DR and BDR of the segment.
* Therefor,e routers only exchange LSAs with the DR and BDR. DROthers will not exchange LSAs with each other.
* All routers will still have the same LSDB, but this reduces the amount of LSAs flooding the network.

![ 250](../_assets/Pasted%20image%2020260621145934.png)

If 6 routers in the same segment share LSAs with each other, the traffic will look like the above picture. As you can see, it is congested. Now how about electing DRs and BDRs?

![ 250](../_assets/Pasted%20image%2020260621150113.png)

The network traffic is now better. Although in modern networks, having heavy traffic in interfaces is not really a problem, having DRs and BDRs will still help removing unnecessary traffic.

* NOTE: **Messages to the DR/BDR are multicast using address `224.0.0.6`**.

![Pasted image 20260621150522.png](../_assets/Pasted%20image%2020260621150522.png)

Here is the quick summary of OSPF neighbor states. DROthers will stop at 'become neighbors' when communicating with other DROthers. The DR and BDR will form a **FULL** adjacency with **ALL** routers in the subnet. DROthers will form a **FULL** adjacency only with the DR/BDR.

![Pasted image 20260621150757.png](../_assets/Pasted%20image%2020260621150757.png)

In `Nbrs F/C` section of `show ip ospf interface brief`, The **F** means number of neighbor routers where **full adjacency** is formed (which is R2 and R4). **C** means the total number of neighbors (R2, R4, and R5).

![ 500](../_assets/Pasted%20image%2020260621151134.png)

Here is the output of `show ip ospf interface g0/0`. In the highlighted section, it says that the Neighbor Count is 3, and the Adjacent neighbor count is 2. Adjacent neighbor is a neighbor where router performs **full adjacency** (which is R2 the BDR and R4 the DR!).

### Point-to-Point Network Type

![Pasted image 20260621161748.png](../_assets/Pasted%20image%2020260621161748.png)

Notice that the connection between R1 and R2 has been changed to **serial connection**.

**Point-to-Point Network Type:**

* Enabled on **serial** interfaces using the **PPP** and **HDLC** encapsulations by default. Both PPP and HDLC are layer 2 encapsulations, which is similar to Ethernet except that they are used on serial connections.
* Routers *dynamically discover* neighbors by sending/listening for OSPF Hello messages using multicast address `224.0.0.5`.
* However, the difference to broadcast network type is that a **DR and BDR are not elected**.
* These encapsulations are used for **point-to-point** connections in which only two routers share network with each other.
* Therefore there is no point in electing a DR and BDR.
* The two routers **will form a Full adjacency** with each other anyway.

### Serial Interfaces

![ 500](../_assets/Pasted%20image%2020260621162357.png)

Serial interfaces are old technology. Modern networks primarily use Ethernet. But it is still worth knowing about them. Notice that the port and cables are different from Ethernet cables.

![ 500](../_assets/Pasted%20image%2020260621162618.png)

* One side of a serial connection functions as DCE (Data Communications Equipment).
* The other side functions as DTE (Data Terminal Equipment).
* The DCE side needs to specify the *clock rate* (speed) of the connection.

![ 500](../_assets/Pasted%20image%2020260621162739.png)

* The command to use to specify the clock rate on DCE is `clock rate *bits-per-second*`. There are accepted clockrates to choose from.
* We set the clock rate to 64000 bits per second (64 kilobits per second) then enabled IP address and disabled shutdown.
* While Ethernet interfaces uses **speed** command to configure interface's operating speed, Serial interfaces use the **clock rate** command.

![ 500](../_assets/Pasted%20image%2020260621163134.png)

* In R1's `show interface s2/0`, notice that the encapsulation type is **HDLC**.
* The default encapsulation on a serial interface is **HDLC**.
  * To be more precise, it is actually **cHDLC** (Cisco HDLC).

Here is the cHDLC structure obtained from Wikipedia:

![Pasted image 20260621163318.png](../_assets/Pasted%20image%2020260621163318.png)

* Notice that *there is no MAC address field*. MAC addresses are not used in cHDLC.

![ 500](../_assets/Pasted%20image%2020260621163447.png)

* To change the encapsulation to PPP, use the `encapsulation ppp` command.
* *If you change the encapsulation, it must match on both ends or the interface will go **down**.*

![Pasted image 20260621163702.png](../_assets/Pasted%20image%2020260621163702.png)

* If you look at the running configuration, notice that on R1's `s2/0` interface is where the clock rate is configured. This is because R1's `s2/0` is the DTE end.
* The `serial restart-delay 0` command is there by default.

![ 500](../_assets/Pasted%20image%2020260621163934.png)
![ 500](../_assets/Pasted%20image%2020260621164106.png)

* To check which side is DCE or DTE, use the command `show controllers *interface-id*` on a serial interface.
* It actually works on Packet Tracer!
* R1's `s2/0` interface is shown as the **DCE**, and the clock rate configured is also shown.
* R2's `s2/0` interface is shown as the **DTE** and it detects the TX (transmit) and RX (receive) clocks on R1.

### OSPF Neighbor Requirements

#### 1. Area number must match

![ 500](../_assets/Pasted%20image%2020260621181512.png)

![Pasted image 20260621181528.png](../_assets/Pasted%20image%2020260621181528.png)

* If you set a different OSPF areas on routers, they won't be detected as OSPF neighbors.

* To fix, use the same area for routers to become OSPF neighbors. In this example, we set the OSPF area of R2 to 0:
  
  ![ 500](../_assets/Pasted%20image%2020260621181715.png)

* Now the router must be shown as an OSPF neighbor:
  ![Pasted image 20260621181748.png](../_assets/Pasted%20image%2020260621181748.png)

#### 2. Interfaces must be in the same subnet

![ 500](../_assets/Pasted%20image%2020260621181840.png)

* Notice that R1 and R2 are in different subnet.

![Pasted image 20260621181914.png](../_assets/Pasted%20image%2020260621181914.png)

* If you activate the OSPF on routers even when using same area, the neighbor router/s won't come up.
* Use the same subnet on a neighbor router's interface the router is linked to.
  ![ 500](../_assets/Pasted%20image%2020260621182118.png)
* Now the routers should be OSPF neighbors after configuring the same subnet.
  ![Pasted image 20260621182159.png](../_assets/Pasted%20image%2020260621182159.png)

#### 3. The OSPF process must not be `shutdown`

![ 500](../_assets/Pasted%20image%2020260621182256.png)

![Pasted image 20260621182312.png](../_assets/Pasted%20image%2020260621182312.png)

* It is actually possible to shut down OSPF using the `shutdown` command!
* Enter OSPF configuration mode and use the `shutdown` command to shutdown the OSPF process.
* The terminal outputs that the neighbors went from **FULL** to **DOWN**.
* If you use `show ip ospf neighbor`, no neighbors will show up.

![Pasted image 20260621182524.png](../_assets/Pasted%20image%2020260621182524.png)

* Just use `no shutdown` inside OSPF configuration mode to turn it back on.
* Now you can see that the neighbors are shown in `show ip ospf neighbor`.

#### 4. OSPF Router IDs must be unique

![ 500](../_assets/Pasted%20image%2020260621182650.png)

![Pasted image 20260621182702.png](../_assets/Pasted%20image%2020260621182702.png)

* Let's assume that no manual configuration and loopback interfaces are not set on both routers. This means that the routers will use their interface IP address as their router ID.
* We set the router ID of R2 to the same value of R1's `g0/0` IP address.
* If you reset the the OSPF, the OSPF will detect duplicate router IDs, as a result, the neighbor stays down!
* You can see that `show ip ospf neighbor` doesn't show the neighbor.

![Pasted image 20260621183314.png](../_assets/Pasted%20image%2020260621183314.png)

* If you remove the configured RID using `no router-id`, the neighbor should show now in `show ip ospf neighbor`.
* The OSPF will automatically re-enable the full adjacency on neighbor router after fixing the issue.
* You don't have to specify the router ID when deleting them!

#### 5. Hello and Dead timers must match

![ 500](../_assets/Pasted%20image%2020260621183558.png)

![Pasted image 20260621183615.png](../_assets/Pasted%20image%2020260621183615.png)

* You can change the hello interval manually using `ip ospf hello-interval *seconds*` command.
* You can also change the dead timer interval manually using `ip ospf dead-interval *seconds*` command.
* If you set a different hello interval and dead interval on R2 (20 seconds hello interval when it is 10 seconds on R1, and 10 seconds dead interval on R2 when it is 40 seconds on R1), the neighbor router will become down.

![Pasted image 20260621183926.png](../_assets/Pasted%20image%2020260621183926.png)

* To reset the hello interval and dead interval to default, use the `no ip ospf hello-interval` and `no ip ospf dead-interval` commands.
* Just like with removing router ID, you don't have to specify which seconds you configured the hello and dead interval to.

#### 6. Authentication settings must match

![ 500](../_assets/Pasted%20image%2020260621184129.png)

![Pasted image 20260621184213.png](../_assets/Pasted%20image%2020260621184213.png)

* You can actually set the OSPF authentication on a router.
* Use `ip ospf authentication-key *key*` to set authentication password.
* Setting the OSPF authentication password alone won't enable authentication on an OSPF enabled router. Use the command `ip ospf authentication` to actually enable it.
* But since authentication is not configured on R1, it will go in down state.

![Pasted image 20260621184427.png](../_assets/Pasted%20image%2020260621184427.png)

* To fix this, use the same authentication settings on R1 or remove the authentication settings on R2.
* In this case, let's remove authentication on R2.
* Use the command `no ip ospf authentication` followed by `no ip ospf authentication-key *configured-key*` to remove the OSPF authentication on an OSPF enabled router.
* After fixing the authentication issue, the routers should enter full adjacency again.

#### 7. IP MTU settings must match

![ 500](../_assets/Pasted%20image%2020260621184708.png)

![Pasted image 20260621184654.png](../_assets/Pasted%20image%2020260621184654.png)

* You can actually configure the IP MTU on a router. The default MTU is usually **1500 bytes**.

* Let's say you configured the MTU to 1400 bytes on R2 using the `ip mtu *value*` command.

* This time, it is different. ***Even if the MTUs are mismatched, the routers can become OSPF neighbors, but OSPF will not operate properly***.

* If you reset the OSPF process, something weird will happen. If you wait a minute, you won't see a notification that the neighbors have reached the full state.

* If you look at `show ip ospf neighbor`, R1 will be stuck in EXSTART state.

* If you wait after minute/s, a few more messages will be displayed:
  ![Pasted image 20260621185745.png](../_assets/Pasted%20image%2020260621185745.png)
  
  This message will keep on repeating by the way!

![Pasted image 20260621185836.png](../_assets/Pasted%20image%2020260621185836.png)

* To reset R2's MTU, use `no ip mtu` (you also don't have to explicitly enter the configured value).
* After resetting the MTU and it will match again with R1's MTU, the neighbors will finally start reaching the OSPF full state.

#### 8. OSPF Network Type must match

![ 500](../_assets/Pasted%20image%2020260621190022.png)

![Pasted image 20260621190043.png](../_assets/Pasted%20image%2020260621190043.png)

* To demonstrate, we set up a loopback interface to R2 and advertised it to R1.
* Then we set up the OSPF network type as **Point-to-Point**.
* However, R1's G0/0 is still using the **Broadcast** network type.
* After configuring the network type, a message will appear that the neighbor went down, but then returned to full state.
* In `show ip ospf neighbor`, R1 will even be displayed as **FULL**.
* So there should be no problem. But we haven't looked at R1 yet.

![Pasted image 20260621190423.png](../_assets/Pasted%20image%2020260621190423.png)

* R2 will actually show in `show ip ospf neighbor` from R1.
* But if you look at routing table, **R2's loopback address won't show**!
* This is tricky. Because everything seems to be working fine. You have to look at the routing table and check if the routes actually show.

### OSPF LSA Types

![Pasted image 20260621190721.png](../_assets/Pasted%20image%2020260621190721.png)

Let's modify the previous network topology a little bit by adding an Internet route to R4. We also advertised the default route to other routers using `default-information originate`.

The OSPF LSDB is made up of LSAs. But there are actually **11 types of LSA**, but there are only **3** you should be aware of for the CCNA:

1. **Type 1 (Router LSA)**
1. **Type 2 (Network LSA)**
1. **Type 5 (AS External LSA)**

* **Type 1 (Router LSA)**
  - Every OSPF router generates this type of LSA.
  - It identifies the router using its router ID.
  - It also lists networks attached to the router's OSPF-activated interfaces.

* **Type 2 (Network LSA)**
  - Generated by the DR of each 'multi-access' network (ie. the **broadcast** network type).
  - Lists the routers which are attached to the multi-access network.

* **Type 5 (AS-External LSA)**
  - Generated by ASBRs to describe routes to destinations outside of the AS (OSPF domain).

![ 500](../_assets/Pasted%20image%2020260621191610.png)

* To view the LSDB of a router, use the command `show ip ospf database`.
* In this case, we viewed the LSDB of R1. It doesn't matter which router to use `show ip ospf database` on since all routers will share the same LSDB.
* In `Router Link States (Area 0)`, all routers generated an LSA identifying their router ID. This view doesn't contain the detailed information of LSAs, but each LSAs actually contain the networks each router is connected to.
* There is only one Type 2 LSA (if you look at `Net Link States (Area 0)` section). Which is generated by R4 on `192.168.2.0/29` subnet. Even though R1, R3, and R5 have DR interfaces, no routers are actually connected to these interfaces so no Type 2 LSAs are generated.
* There is one Type 5 LSA (if you look at `Type-5 AS External Link States` section). It is generated by R4 which is connected to the default route which is outside the OSPF area.
