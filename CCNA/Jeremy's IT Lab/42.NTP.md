### The importance of time

* All devices have an internal clock whether it be routers, switches, PC, etc.

* **`show clock`**: This is a Cisco IOS command to view the time. It is often displayed in **UTC (Universal Coordinated Time)** which is the default time zone.
  ![ 300](../_assets/Pasted%20image%2020260707215911.png)

* **`show clock detail`**: this command let's you see the *time source*. The **hardware calendar** is the default time source.
  ![ 300](../_assets/Pasted%20image%2020260707220006.png)
  
  **NOTE:** the asterisk (\*) before the time means it is not considered authoritative.

* From a CCNA perspective, <u>the most important reason to have accurate time on a device is to have accurate logs for troubleshooting</u>.

* **Syslog**, the protocol used to keep device logs, will be covered in a later video.

* Although the hardware calendar (built-in clock) is the default time-source, the hardware clock and software clock are separate and can be configured separately.

### Network Time Protocol Intro

* Manually configuring the time on devices is not scalable.
* The manually configured clocks will drift, resulting in inaccurate time.
* **NTP (Network Time Protocol)** allows automatic syncing of time over a network.
* NTP clients request the time from NTP servers.
* A device can be an NTP server and an NTP client at the same time.
* NTP allows accuracy of time within ~1 millisecond if the NTP server is in the same LAN, or withing ~50 milliseconds if connecting to the NTP server over a WAN/the Internet.
* Some NTP servers are 'better' than others. The 'distance' of an NTP server from the original **reference clock** is called **stratum**.
* NTP uses UDP port 123 to communicate.

---

### Reference Clocks

* A reference clock is usually a very accurate time device like an atomic clock or a GPS clock.
* Reference clocks are **stratum 0** within the NTP hierarchy.
* NTP servers directly connected to reference clocks are **stratum 1**

### NTP Hierarchy

![ 500](../_assets/Pasted%20image%2020260708213829.png)

* Reference clocks are **stratum 0**.
* **Stratum 1** NTP servers get theirtime from reference clocks.
* **Stratum 2** NTP servers get their time from stratum 1 NTP servers.
* **Stratum 3** NTP servers get their time from stratum 2 NTP servers.
* **Stratum 15** is the maximum. Anything above that is considered unreliable.
* Devices can also 'peer' with devices at the same stratum to provide more accurate time. This is called **symmetric active** mode. Cisco devices can operate in three NTP modes:
  - Server mode
  - Client mode
  - Symmetric active mode
  **NOTE:** Cisco devices can also operate in three modes at the same time.
* An NTP client can sync to multiple NTP servers.

#### `do show clock detail`

![Pasted image 20260708222014.png](../_assets/Pasted%20image%2020260708222014.png)

NTP uses only the UTC time zone. You must configure the appropriate time zone on each device.

NTP doesn't update the calendar by default, so you have to set it and sync it yourself. **`ntp update-calendar`** configures the router to update the hardware clock (calendar) with the time learned via NTP.

Why is it important to sync the hardware clock? The hardware clock tracks the date and time on the device even if it restarts, power is lost, etc. When the system is restarted, the hardware clock is used to initialize the software clock.

For learning purposes, let's use R1 as NTP source for R2. You usually use Google NTP servers for all routers in real practice.

### NTP Server Mode

![ 500](../_assets/Pasted%20image%2020260709055333.png)

If one of the devices (NTP client) can sync to the NTP server, it can act as NTP server too, and the other devices can connect to it. But what if there is no NTP server to sync to?

Even if slightly inaccurate, you probably want the devices to sync their time.

![Pasted image 20260709055703.png](../_assets/Pasted%20image%2020260709055703.png)

**`ntp master`** will make the device act as NTP master clock.

![Pasted image 20260709060552.png](../_assets/Pasted%20image%2020260709060552.png)

R1 will use the loopback address as its NTP source. *Loopback address is different from loopback interface*. While loopback interface can be advertised through OSPF, the loopback address (starting with `127.~`) is internal to the devices and can't be reach by other devices through dynamic routing.

* The reference clock (loopback address) will be **stratum 7**
* R1 (the client and NTP master) will be **stratum 8**

### NTP Authentication

* NTP authentication can be configured, although it is optional.
* It allows NTP clients to ensure they only sync to the intended servers.
* To configure NTP authentication:
  - **`ntp authenticate`**: Enable NTP authentication
  - **`ntp authenticate-key *key-number* md5 *key*`**: Create the NTP authentication key(s)
  - **`ntp trusted-key *key-number*`**: Specify the trusted key(s)
  - **`ntp server *ip-address* key *key-number*`**: Specify which key to use for the server. This command isn't needed on the server (R1).
