### The Purpose of DHCP

* DHCP is used to allow hosts to automatically/dynamically learn various aspects of their network configuration, such as IP address, subnet mask, default gateway, DNS server, etc, without manual/static configuration.
* It is an essential part of modern networks.
  - When you connect a phone/laptop to WiFi, do you ask the network admin which IP address, subnet mask, default gateway, etc, the phone/laptop should use?
* Typically used for 'client devices' such as workstations (PCs), phones, etc. Devices such as routers, servers, etc, are usually manually configured.
* In small networks (such as home networks) the router typically acts as the DHCP server hosts in the LAN.
* In larger networks, the DHCP server is usually a Windows/Linux server.

You can confirm that you are using DHCP if the following are checked:

* **Obtain an IP address automatically**
* **Obtain DNS server address automatically**

![Pasted image 20260713050100.png](../_assets/Pasted%20image%2020260713050100.png)

Let's use the command `ipconfig /all` to confirm that we are using DHCP. If **DHCP enabled** says **Yes**, it is confirmed we are using DHCP.

![Pasted image 20260713050406.png](../_assets/Pasted%20image%2020260713050406.png)

* In the **IPv4 Address** row, the automatically assigned address is labeled as **Preferred**. This means that this PC was *previously assigned this IP address by the DHCP server*, so it asked to receive the **same address** again this time. If the IP address is no longer available, the DHCP server will give a new address. But since the IP address is still available, the PC got the preferred IP address.
* The **Lease Obtained** and **Lease Expires** row shows the 'lease' time. DHCP server 'lease' IP address to clients. These leases are usually not permanent, and the client must give up the address at the end of the lease. If the client no longer needs the address, a client can also give up the address before the lease is up.
* While you can set the leases to be *permanent* (optionally), meaning DHCP can permanently assign IP addresses, it is always better to set a lease time. For example, in public WiFis such as cafes, it is not ideal to set the DHCP server to give IP address permanently to customers, because that IP address cannot be used by other customers unless the current address holder give the IP address up.
* The **Default Gateway**, **DHCP Server**, and **DNS Server** all have the same IP address of `192.168.0.1`, which is the address of the home router. This is common to home networks as these services are all provided by the home router.

Let's demonstrate the process what does DHCP clients goes through to get an IP address from the DHCP server.

**Using `ipconfig /release`:**

`ipconfig /release` let's the DHCP client release the received address from the DHCP server.

![Pasted image 20260713052632.png](../_assets/Pasted%20image%2020260713052632.png)

Here are some fields that is pretty interesting to know inside DHCP release payload:

* The **Client IP address** (The DHCP client, which is the PC).
* The **Magic Cookie: DHCP** (do a Google search!)
* The **Options** field: there are various options for different services DHCP can use. For example, Options 53 indicates what kind of DHCP it is.

**Using `ipconfig /renew`:**

![Pasted image 20260713053304.png](../_assets/Pasted%20image%2020260713053304.png)

`ipconfig /renew` will renew the IP address to be received by a DHCP client from the DHCP server. If you enter `ipconfig /all` after `ipconfig /renew`, you can see that the IPv4 address, Default Gateway, DHCP Server, DNS Servers, etc, are filled up again and is automatically configured by DHCP.

Under the hood, `ipconfig /renew` process involves 4 messages. Which is discussed in the next sections.

### DHCP Discover Message

![Pasted image 20260713053647.png](../_assets/Pasted%20image%2020260713053647.png)

(Wireshark Capture)

![Pasted image 20260713053908.png](../_assets/Pasted%20image%2020260713053908.png)

* DHCP Discover uses broadcast, so DHCP Discover is sent to MAC **`FFFF.FFFF.FFFF`**.
* Since the client still don't have an IP address, it uses a Source IP of **`0.0.0.0`**. The Destination IP is also **`255.255.255.255`** meaning that it is a broadcast message.
* If the client previously learned an IP address from DHCP, it will request the same IP address if available, as indicated by **Option 50** field.

---

### DHCP Offer Message

![Pasted image 20260713054246.png](../_assets/Pasted%20image%2020260713054246.png)

(Wireshark Capture)

![Pasted image 20260713054442.png](../_assets/Pasted%20image%2020260713054442.png)

* Since in the DHCP Discover stage, the DHCP Server is learned, DHCP Offer message is sent by the DHCP Server using a **Unicast** frame.
* Whether the DHCP Offer will be sent as a unicast or broadcast depends on the Client's request, which is indicated in the **Bootp flags** field.
* At this point in the DHCP process, the IP address isn't actually configured (the address is still 'offered'). Some clients won't accept a unicast message before their IP address is actually configured. So sometimes broadcast DHCP Offer messages is sent as broadcast instead of unicast.

---

### DHCP Request Message

![Pasted image 20260713055043.png](../_assets/Pasted%20image%2020260713055043.png)

* This stage is important.
* There may be multiple DHCP servers that will receive the DHCP Discover message (since it is broadcast, and there might be more than one DHCP server on the LAN), so they might all send DHCP Offer messages to the same client. So the client will make sure which IP address from which DHCP server will it accept an offered IP address.
* Typically, it accepts the IP address it first received.

(Wireshark Capture)

![Pasted image 20260713055539.png](../_assets/Pasted%20image%2020260713055539.png)

* DHCP Request is sent as **broadcast** by the client.
* If there are more than one DHCP server on the LAN, all of them will receive the DHCP Request message.
* With the **Options 54** field, the *DHCP Server Identifier* is indicated which tells which DHCP server does the client selected so the other DHCP servers can know.

### DHCP Relay

* Some network engineers might choose to configure each router to act as the DHCP server for its connected LANs.
* However, large enterprises often choose to use a centralized DHCP server.
* If the server is centralized, it won't receive the DHCP clients' broadcast DHCP messages. (broadcast messages don't leave the local subnet)
* To fix this, you can configure a router to act as a **DHCP relay agent**.
* The router will forward the clients' broadcast DHCP messages to the remote DHCP server as unicast messages.

![Pasted image 20260713062451.png](../_assets/Pasted%20image%2020260713062451.png)

For the example network, SRV1 will serve as the central DHCP server. R1 will serve as the DHCP relay agent.

Here is the diagram how R1 forwards DHCP Discover and DHCP Request on behalf of PC1 to central DHCP server (SRV1). SRV will then reply with DHCP Offer and DHCP Ack to R1, and R1 will send it to PC1.
