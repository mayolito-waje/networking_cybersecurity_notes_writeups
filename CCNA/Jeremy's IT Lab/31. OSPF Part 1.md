### Review: Link State Routing Protocols

* When using a **link state** routing protocol, every router creates a 'connectivity map' of the network.
* To allow this, each router advertises information about its interfaces (connected networks) to its neighbors. These advertisements are passed along to other routers, until all routers in the network develop the same map of the network.
* Each router independently uses this map to calculate the best routes to each destination.
* Link state protocols use more resources (CPU) on the router, because more information is shared.
* However, link state protocols tend to be faster in reacting to changes in the network than distance vector protocols.

---

### OSPF Intro

* OSPF = **Open Shortest Path First**
* OSPF uses **Dijkstra's algorithm**, which was developed by Dutch computer scientist Edsger Dijkstra.
* There are three versions of OSPF:
  * **OSPFv1** (1989): old version, not in use anymore
  * **OSPFv2** (1998): used for **IPv4**
  * **OSPFv3** (2008): used for **IPv6** (can also be used for IPv4, but usually v2 is used)
* Routers store information about the network in **LSA**s (Link State Advertisements), which are organized in a structure called the **LSDB** (Link State Database).
* Routers will **flood** LSAs until all routers in the OSPF *area* develop the same map of the network (LSDB)

### LSA Flooding

![ 300](../../Pasted%20image%2020260615050223.png)

* Let's say the routers all have OSPF enabled and contain the same LSDBs. This makes all the routers OSPF neighbors.
* R4 wants to tell neighbors about its newly OSPF enabled `G0/0` interface which contains the IP address `192.168.4.0/24`.
* R4 will use **LSA flooding** to update the LSDB of other OSPF neighbors. The LSA to be flooded will look like this:
  ![ 200](../../Pasted%20image%2020260615050457.png)

![ 300](../../Pasted%20image%2020260615050542.png)

* The LSA is flooded throughout the network until all routers have received it.
* This results in all routers in the *area* sharing the **same LSDB**.
* The LSDB looks like this:
  ![ 200](../../Pasted%20image%2020260615050849.png)
  The LSDB contain LSAs from all the different links over the network.
* After the OSPF is enabled on R4's `G0/0` interface, the new LSA will be added to all neighbor's LSDB:
  ![ 200](../../Pasted%20image%2020260615051108.png)
* This results in all routers sharing the same LSDB.
* Each router then uses the SPF algorithm to calculate its best route to `192.168.4.0/24`.
* **NOTE:** Each LSA has an aging timer (**30 min** by default). The LSA will be flooded again after the timer expires.

### Basic Process of OSPF

In OSPF, there are three main steps in the process of sharing LSAs and determining the best route to each destination in the network.

1. A router **becomes neighbors** with other routers connected to the same segment.
1. **Exchange LSAs** with neighbor routers.
1. Each router will **independently calculate the best routes** to each destination, and insert them into the routing table.

### OSPF Areas

OSPF uses **areas** to divide up the network. It is unique to OSPF (RIP and EIGRP doesn't have it).

![ 300](../../Pasted%20image%2020260615052355.png)

The topology above is an example of a *small network*. Small networks can be *single-area* without any negative effects on performance. However in larger networks, a single-area design can have negative effects:

* the SPF algorithm takes more time to calculate routes
* the SPF algorithm requires exponentially more processing power on the routers
* the larger LSDB takes up more memory on the routers
* any small change in the network causes every router to flood LSAs and run the SPF algorithm again

By dividing a large OSPF network into several smaller areas, you can avoid the above negative effects. Here is an example of a large network that would need more than one OSPF area:

![ 500](../../Pasted%20image%2020260615052835.png)

It's possible to assign this large network to a single-area.

![ 500](../../Pasted%20image%2020260615053101.png)

The entire network is placed in **Area 0** which is also known as the **backbone area** (we will learn about this later). However, there is a more elegant solution for such large network:

![ 500](../../Pasted%20image%2020260615053226.png)

To understand areas more, let's study the terminologies and rules.

#### OSPF Area Terminologies

* An **area** is a set of routers and links that share the same LSDB. In the example above, there are **four areas** (Area 0, Area 1, Area 2, Area 3). Each of these areas maintain a unique LSDB

* The **backbone area** (area 0) is a special area that all other areas must connect to. Area 1, area 2, and area 3 all connects to the backbone area. To understand this further, the following topology is NOT allowed in OSPF:
  ![ 500](../../Pasted%20image%2020260615053733.png)
  
  The router can only connect to the backbone area. The router cannot connect between area 1 and area 2!

* Routers with all interfaces in the same area are called **internal routers**.
  ![ 500](../../Pasted%20image%2020260615054149.png)
  
  The routers highlighted in **red box** are the internal routers.

* Routers with interfaces in multiple areas are called **area border routers** (ABRs).
  ![ 500](../../Pasted%20image%2020260615054338.png)
  
  The routers connected to backbone area and other area (inside **red boxes**) are the ABRs. ABRs maintain a *separate LSDB* for each area they are connected to. It is recommended that you connect an ABR to a maximum of **2 areas**. Connecting an ABR to 3+ areas can overburden the router.

* Routers connected to the backbone area (area 0) are called **backbone routers**.
  ![ 500](../../Pasted%20image%2020260615054730.png)

* An **inter-area route** is a route to a destination inside the same OSPF area.
  ![ 500](../../Pasted%20image%2020260615054909.png)
  
  If a router learns about the subnet within the same OSPF area, it is called inter-area route.

* An **intra-area route** is a route to a destination in a different OSPF area.
  ![ 500](../../Pasted%20image%2020260615055044.png)
  
  If a router from are 1 learns about the subnet from area 2, it is calle intra-area route.

* **OSPF areas should be *contiguous*.**
  
  ![ 500](../../Pasted%20image%2020260615055743.png)

* **All OSPF areas must have at least one ABR connected to the backbone area.**

### Basic OSPF Configuration

![ 250](../../Pasted%20image%2020260615205801.png)

Although it is important to know about OSPF areas, in CCNA we only need to configure single-area OSPF. In this example, we set the network to OSPF Area 0. Let's assume that we already configured OSPF on R2, R3, and R4. So let's configure OSPF on R1.

![ 500](../../Pasted%20image%2020260615210049.png)

* `router ospf ?`: enter OSPF configuration mode. The ? is the process ID. A router can run multiple OSPF processes at once, but we only typically need to run one process. Let's say you chose **1** as the OSPF process ID.
  * While in EIGRP, the AS number should be the same for the routers to become neighbors, the OSPF *process ID* is **locally significant**. Routers with different process IDs can become OSPF neighbors.
* `network 10.0.12.0 0.0.0.3 area 0`: just like in EIGRP, you enable OSPF on interfaces based on IP range. OSPF also uses wildcard mask (`0.0.0.3`) to match IP addresses. The OSPF `network` command, however, requires you to specify the **area**.
  * For the CCNA, you only need to configure single-area OSPF (area 0). While you can use any area number, it is a best practice to use area 0.

### `passive-interface` Command

![ 500](../../Pasted%20image%2020260615211143.png)

* You already know this command from RIP and EIGRP.
* The **passive-interface** command tells the router to stop sending OSPF 'hello' messages out of the interface.
* However, the router will continue to send LSAs informing it's neighbors about the subnet configured on the interface.
* You should always use this command on interfaces which don't have any OSPF neighbors.

### `show ip protocols`

![ 500](../../Pasted%20image%2020260615211926.png)

After setting up OSPF on R1, use `show ip protocols` to check on OSPF configuration. The routing protocol says `ospf 1` just like we configured earlier.

The router ID is `172.16.1.14`. The Router ID is determined in exactly the same way as EIGRP:
1. Manual configuration
2. The highest IP address on a loopback interface
3. Highest IP address on a physical interface

Since we haven't configured a loopback or manually setting router ID, the router ID is the highest IP on interface which is `172.16.1.14`. To change the router ID, use the following command: `router-id ?`:

![ 500](../../Pasted%20image%2020260615212423.png)

Setting up router ID on OSPF is a little different from EIGRP because in EIGRP you have to manually specify the `eigrp` keyword (`eigrp router-id ?`).

We set the router ID to `1.1.1.1`. But for it to take effect, you have to reset the router first or use the command `clear ip ospf process` otherwise the router ID will remain the same as `172.16.1.14`.

![ 500](../../Pasted%20image%2020260615212908.png)

This is a bad idea in a real network, and the router will lose all of its OSPF routes for a short time and will lose all the known paths to the destination. By default, `clear ip ospf process` question uses `no` as an answer.

After clearing the OSPF process, the router ID will now be `1.1.1.1` through checking it using `show ip protocols`.
