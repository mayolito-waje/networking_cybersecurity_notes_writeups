### FHRP Intro

![ 500](../_assets/Pasted%20image%2020260622050757.png)

We learned why redundancy is a good practice when studying about spanning trees. Redundancy allows network devices to communicate with each other if one of the link fails due to some issues. For example, if one of the link to access the internet got broken, there should be an alternative path for the network devices to use to access the internet.

But there is a problem though, if R1 is the default path to talk to internet, R1's IP (`172.16.0.254`) would be configured as the default gateway of end hosts. So, when end hosts communicate to the internet, it will look like this:

![ 500](../_assets/Pasted%20image%2020260622051312.png)

So, what if R1 fails? How can end hosts know that R1 fails? If R1 fails, the end hosts will not know that it fails! Even though R2 is there as an alternative, the configured default gateway on the end hosts uses R1's IP.

![ 500](../_assets/Pasted%20image%2020260622051443.png)

Enter **First Hop Redundancy Protocol** (FHRP). According to Wikipedia, FHRP is:

 > 
 > ***A first hop redundancy protocol (FHRP) is a computer networking protocol which is designed to protect the default gateway used on a subnetwork by allowing two or more routers to provide backup for that address; in the event of failure of an active router, the backup router will take over the address, usually within a few seconds.***

#### How does FHRP work?

R1 and R2 will share the same **Virtual IP Address**, let's use a VIP of `172.16.0.252` for both routers to share to. In addition, end hosts will also use the VIP as the default gateway:

![ 500](../_assets/Pasted%20image%2020260622052155.png)

The routers will then negotiate with each other to determine which should be active and standby using **multicast hello messages**.

![ 500](../_assets/Pasted%20image%2020260622052347.png)

After some time, the roles of router might be negotiated, the role might vary based on what FHRP you use:

![ 500](../_assets/Pasted%20image%2020260622052425.png)

R1 will become **active** and R2 will be on **standby**. If R1 fails, R2 can serve as the backup router. But before the end hosts can communicate with the VIP, it will of course need to know its MAC address using **ARP**:

![ 500](../_assets/Pasted%20image%2020260622052659.png)
![ 500](../_assets/Pasted%20image%2020260622052731.png)
![ 500](../_assets/Pasted%20image%2020260622052810.png)

But who will send the ARP reply? Since R1 is the **active** router on the VIP, it is the one who will send an ARP reply.

![ 500](../_assets/Pasted%20image%2020260622052937.png)

Aside from virtual IP address, R1 will also send a **virtual MAC address** as a known unicast frame to reply to end host. Now PC1 know the MAC address of the VIP. If PC wants to communicate outside the subnet (internet), it will reach the default gateway (the virtual IP):

![ 500](../_assets/Pasted%20image%2020260622053251.png)

The frame will be sent to R1, and the packet will be sent over the Internet. So what if R1 fails? R2 will come to the rescue since they share the same virtual IP:

![ 500](../_assets/Pasted%20image%2020260622053428.png)
![ 500](../_assets/Pasted%20image%2020260622053518.png)

If the active router on VIP changes, does the PC needs to update its ARP cache? **No**. Remember that the PC maps the virtual IP to vritual MAC address instead of R1's MAC address:

![ 350](../_assets/Pasted%20image%2020260622053703.png)

So, how will the network map the virtual MAC to R2? ***The switches will update their MAC address table.*** How? R2 will send a **gratuitous ARP reply** and will be **broadcasted** over the switches. *An **ARP Reply** that sends a **broadcast**?*

#### Gratuitous ARP Reply

* Gratuitous ARP are ARP replies that is *sent without being requested*.
* This means that no ARP reply will be sent without receiving an ARP request first.
* Normal ARP replies are unicast, but gratuitous ARP is a **broadcast** and will be sent to `ff:ff:ff:ff:ff:ff`.
* This means that gratuitous ARP will be **flooded** so the switch can learn which interface does the virtual MAC come from.

![ 500](../_assets/Pasted%20image%2020260622054433.png)
![ 500](../_assets/Pasted%20image%2020260622054523.png)

Now that R2 is the new active router on the virtual IP, PC1 will still use the same destination MAC to talk to the internet. But this time, the path will traverse to R2 to reach the internet.

![ 500](../_assets/Pasted%20image%2020260622054837.png)

What if R2 returns and become functional again? Will it become the active router?

![ 500](../_assets/Pasted%20image%2020260622055104.png)

***FHRPs are 'non-preemptive'. the current active router will not automatically give up its role, even if the former active router returns***. You can change this setting to make R1 'preempt' R2 and take back its active role automatically.

### HSRP (Hot Standby Router Protocol)

* Is a Cisco proprietary.
* An **active** and **standby** router are elected.
* There are two versions: **version 1** and **version 2**. Version 2 adds IPv6 support and increases the number of *groups* that can be configured.
* Multicast IPv4 address:
  v1 = `224.0.0.2`
  v2 = `224.0.0.102`
* Virtual MAC address:
  v1 = `0000.0c07.acXX` (XX = HSRP group number)
  v2 = `0000.0c9f.fXXX` (XXX = HSRP group number)
* In a situation with multiple subnets/VLANs, you can configure a different active router in each subnet/VLAN to load balance.

Using multiple subnets and VLANs, the active routers can be different in a different VLAN/subnet:

![ 500](../_assets/Pasted%20image%2020260622062909.png)

### VRRP (Virual Router Redundancy Protocol)

* Open standard
* A **master** and **backup** router are elected.
* Multicast IPv4 address: `224.0.0.18`
* Virtual MAC address: `0000.5e00.01XX` (XX = VRRP group number)
  e.g. If VRRP group number is 200, the virtual MAC will be `0000.5e00.01c8` since 200 = 0xC8 in hexadecimal.
* In a situation with multiple subnets/VLANs, you can configure a different master router in each subnet/VLAN to load balance.

So, using VRRP, the master routers can be different depending on the subnet/VLAN:

### GLBP (Gateway Load Balancing Protocol)

* Cisco proprietary
* Load balances among multiple routers <u>within a single subnet</u>.
  FOR EXAMPLE: PC1 and PC2 are both in VLAN 1, PC1 will use R1 as its default gateway and PC2 will use R2 as its default gateway.
* An **AVG (Active Virtual Gateway)** is elected.
* Up to four **AVFs (Active Virtual Forwarders)** are assigned by the AVG (the AVG itself can be an AVF, too).
* Each AVF acts as the default gateway for a portion of the hosts in the subnet.
* Multicast IPv4 address: `224.0.10.102`
* Virtual MAC address: `0007.b400.XXYY` (XX = GLBP group number, YY = AVF number).
  FOR EXAMPLE: If GBLP is 1 and AVF is 1, then the virtual MAC address is `0007.b400.0101`

### HSRP Configuration

![ 250](../_assets/Pasted%20image%2020260623045233.png)

We will use a simple topology to demonstrate how to configure HSRP on a basic level. There will be two routers to use and we will configure HSRP on it on `172.16.0.0/24` subnet.

![ 500](../_assets/Pasted%20image%2020260623045421.png)

* Let's configure HSRP on R1's G0/0 interface. Make sure that the interface you will config to is right! In this case R1' G0/0 is linked to the target subnet.
* HSRP is configured with `standby ?` command. Let's focus on HSRP group number.
  **For HSRP V1:** the maximum group number is **255** (V1 is the default).
  **For HSRP V2:** the maximum group number is **4095**.
* To use HSRP version 2, use the command `standby version 2`. If you check the `standby ?` again, you can see that the group number has been changed from 0 to 4095.|
  ![ 500](../_assets/Pasted%20image%2020260623045855.png)

![ 500](../_assets/Pasted%20image%2020260623050020.png)

* Let's use HSRP Group number 1. It's not a convention, but matching the HSRP group with the VLAN number is nice.
  **REMEMBER:** The group number should be consistent on every router connecting to the same subnet. This means R2 G0/0 should also use HSRP group number 1.

![ 500](../_assets/Pasted%20image%2020260623050322.png)

* The command `standby *group-number* ip *ip-address*` is the command you will use to set the virtual IP address on an HSRP group.
* In this case, we used to command `standby 1 ip 172.16.0.254` to set the default gateway on HSRP group 1 inside R1's G0/0 interface.
* `standby *group-number* priority *value*` is used to determine which router will be the **active** router. The **active router** is determined in this order:
  1. Highest priority (default **100**)
  2. Highest IP address
* R1 will become the active router because it has a priority of 200. But even without configuring the priority, R1 will still become the active router because it has higher IP address compared to R2.
* `standby *group-number* preempt` is the last basic HSRP command we will learn. **Preempt** causes the router to take the role of active router, even if another router already has the role. This command is only necessary on the router you want to become active.
  **NOTE:** preemption only works if the router has higher priority than the current active router.

![ 500](../_assets/Pasted%20image%2020260623051436.png)

* Now let's configure R2.
* We also used version 2 on R2 since we configured R1 to use version 2. ***HSRP version 1 and version 2 are not compatible. If R1 uses version 2, R2 must use version 2 also.***
* We also configured the same virtual IP on R2 using the command `standby 1 ip 172.16.0.254`.
* We set the priority to 50 (`standby 1 priority 50`) and also enabled preemption (`standby 1 preempt`). Both commands are unnecessary. R1 already has higher priority than R2, and preemption doesn't need to be enabled on a standby router.

![ 500](../_assets/Pasted%20image%2020260623051916.png)

* `show standby` is a command to check the HSRP configuration of the router. Let's focus on R1 output.
* It shows `GigabitEthernet0/0 - Group 1 (version 2)` which means we enabled HSRP on G0/0 using HSRP group number 1 and HSRP version 2.
* `State is Active` means R1 is the **active router**.
* `Virtual IP address is 172.16.0.254` shows the configured virtual IP address on the interface.
* The 2 lines after the virtual IP shows the virtual MAC address the interface uses.
* The Hello time uses default values since we didn't configured it.
* `Preemption enabled` means we enabled preemption on the router.
* `Active router is local` because R1 itself is the active router.
* `Standby router is 172.16.0.252,...` shows that R2 is the standby router.
* `Priority 200 (configured 200)` shows the manually configured priority on the router.
