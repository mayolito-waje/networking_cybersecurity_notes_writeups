### IPv6 Address Representation

* An **RFC** (Request for Comments) is a publication from the ISOC (Internet Society) and associated organizations like the IETF (Internet Engineering Task Force), and are the official documents of Internet specifications, protocols, procedures, etc.
* **RFC 5952** is '**A Recommendation for IPv6 Address Text Representation**'
* Before this RFC, IPv6 address representation was more flexible
  - You could remove leading 0s, or leave them
  - You could replace all-0 quartets with `::`, or leave them
  - You could use upper-case 0xA, B, C, D, E, F, or lower-case 0xa, b, c, d, e, f
* RFC 5952 suggests standardizing IPv6 address representation.

**RFC 5952 IPv6 Address Representation:**

* Leading 0s MUST be removed.
  `2001:0db8:0000:0001:0f2a:4fff:fea3:00b1`
  **-->** `2001:db8:0:1:f2a:4fff:fea3:b1`

* `::` MUST be used to shorten the longest string of all-0 quartets.
  (if there is only one all 0-quartet, don't use `::`)
  `2001:0000:0000:0000:0f2a:0000:0000:00b1`
  **-->** `2001::f2a:0:0:b1`

* If there are two equal-length choices for the `::`, use `::` to shorten the one on the left.
  `2001:0db8:0000:0000:0f2a:0000:0000:00b1`
  **-->** `2001:db8::f2a:0:0:b1`

* Hexadecimal characters 'a', 'b', 'c', 'd', 'e', and 'f' MUST be written using lower-case, NOT upper-case A B C D E F
  
  ![ 500](../_assets/Pasted%20image%2020260701060214.png)
  
  However, even Cisco get them wrong because they display IPv6 in uppercase hexadecimal characters when using Cisco CLI so it's not a really hard rule.

### IPv6 Header

![ 500](../_assets/Pasted%20image%2020260701060332.png)

IPv6 Header is much simpler than IPv4! Compared to IPv4 which has variable header length (options field can go up to 40 bytes, which makes the entire IPv4 header go up to 60 bytes), IPv6 has **fixed** header length, which is **40 bytes**.

---

### IPv6 Header - Version

* Length: 4 bits
* Indicates the version of IP that is used.
* Fixed value of 6 (`0b0110`) to indicate IPv6.

---

### IPv6 Header - Traffic Class

* Length: 8 bits
* Used for QoS (Quality of Service), to indicate high-priority traffic.
* For example IP phone traffic, live video calls, etc, will have a Traffic Class value which gives them priority over other traffic.

---

### IPv6 Header - Flow Label

* Length: 20 bits
* Used to identify specific traffic 'flows' (communications between a specific source and destination).

---

### IPv6 Header - Payload Length

* Length: 16 bits
* Indicates the length of the payload (the encapsulated Layer 4 segment) <u>in bytes</u>.
* For example, if the payload is 1024 bytes, the value of payload length will be 1024.
* The length of the IPv6 header itself **isn't included**, because the header is fixed length (40 bytes).

---

### IPv6 Header - Next Header

* Length: 8 bits
* Indicates the type of the 'next header' (header of the encapsulated segment), for example TCP or UDP.
* Same function as the IPv4 header's 'Protocol' field.

---

### IPv6 Header - Hop Limit

* Length: 8 bits
* The value in this field is decremented by 1 by each router that forwards it. If it reaches 0, the packet is discarded.
* Same function as the IPv4 header's 'TTL' field.

---

### IPv6 Header - Source/Destination

* Length: 128 bits each
* These fields contain the IPv6 addresses of the packet's source and the packet's intended destination.

### Neighbor Discovery Protocol

* Neighbor Discovery Protocol (NDP) is a protocol used with IPv6.
* It has various functions, and one of those functions is to replace ARP, which is no longer used in IPv6.
* The ARP-like function of NDP uses ICMPv6 and solicited-node multicast addresses to learn the MAC address of other hosts.
  (\*ARP in IPv4 uses broadcast messages)
* Two message types are used:
  1. **Neighbor Solication (NS)** = ICMPv6 Type 135
  NDP equivalent of ARP Request
  2. **Neighbor Advertisement (NA)** = ICMPv6 Type 136
  NDP equivalent of ARP Reply

---

### Neighbor Solicitation (NS)

![ 500](../_assets/Pasted%20image%2020260702051821.png)

Let's say we typed `ping 2001:db8::78:9abc` on R1 to ping R2, how does Neighbor Solicitation work?

R1 will encapsulate the packet in an Ethernet frame, so it needs to know R2's MAC address. To know R2's MAC address, R1 will send a Neighbor Solicitation message.

![ 500](../_assets/Pasted%20image%2020260702052236.png)

To understand the difference to an ARP request message, let's look at the different address in captured packet frame:

![Pasted image 20260702052457.png](../_assets/Pasted%20image%2020260702052457.png)

The solicited-node multicast address is used as Destination IP in Neighbor Discovery process. How does R1 automatically know the solicited-node multicast address of R2? Since we used `ping` command along with R2's MAC, R1 automatically calculated to solicited-node multicast address.

The IP also used multicast MAC based on R2's solicited-node address as Destination MAC Address. It is not a CCNA topic so we don't have to deep dive into it. Just know the difference between ARP Request and Neighbor Solicitation. ARP Request uses broadcast, while NS use multicast.

### NDP - Router Solicitation/Advertisement

* Another function of NDP allows hosts to automatically discover routers on the local network.
* Two messages are used for this process:

1. **Router Solicitation (RS)** = ICMPv6 Type 133
   - Sent to multicast address `FF02::2` (all routers)
   - Asks all routers on the local link to identify themselves.
   - Sent when an interface is enabled/hosts is connected to the network.

1. **Router Advertisement (RA)** = ICMPv6 Type 134
   - Sent to multicast address `FF02::1` (all nodes).
   - The router announces its presence, as well as other information about the link.
   - These messages are sent in response to RS messages.
   - They are also sent periodically, even if the router hasn't received an RS.

![ 500](../_assets/Pasted%20image%2020260704092626.png)

To give a brief demonstration, let's use R1 and R2 again. Router Solicitation/Advertisement isn't only unique to routers. Although only routers send RAs, all IPv6 hosts will send RS when they come online.

![ 500](../_assets/Pasted%20image%2020260704092929.png)

Let's say we enable R2's G0/0 interface. It automatically sends router solicitation message asking if there is any router/s on the link. R1 replies, identifying itself. There are a lot of ways this can be used, for example learning default gateways from RA messages.

### SLAAC

* Stands for **Stateless Address Auto-configuration**.
* Hosts use the RS/RA messages to learn the IPv6 prefix of the local link (ie. `2001:db8::.64`), and then automatically generate an IPv6 address.
* Using the <code>ipv6 address *prefix/prefix-length* eui-64</code> command, you need to manually enter the prefix.
* Using the `ipv6 address autoconfig` command, you don't need to enter the prefix. The device uses NDP to learn the prefix used on the local link.
* The device will use EUI-64 to generate the interface ID, or it will be randomly generated (depending on the device/maker)

![ 500](../_assets/Pasted%20image%2020260704093714.png)

For example, R1 is connected to R2. R1 is configured with an IPv6 address, but R2 doesn't have one yet. By using the command `ipv6 address autoconfig`, it will automatically generate a global unicast and local-link address after the NDP process.

Keep in mind that SLAAC is not unique to Cisco. It is a standard IPv6 function and end hosts such as PCs can also perform it.

### Duplicate Address Detection (DAD)

* Duplicate Address Detection (DAD) allows hosts to check if other devices on the local link are using the same IPv6 address.
* Any time an IPv6-enabled interface initializes (`no shutdown` command), or an IPv6 address is configured on an interface (by any method: manual, SLAAC, etc.), it performs DAD.
* DAD uses two messages your learned earlier: NS and NA.
* The host will send an NS to its own IPv6 address. If it doesn't get a reply, it knows the address is unique.
* If it gets a reply, it means another host on the network is already using the address.

### IPv6 Static Routing

* IPv6 routing works the same as IPv4 routing.
* However, the two processes are separate on the router, and the two routing tables are separate as well.
* IPv4 routing is enabled by default.
* IPv6 routing is disabled by default, and must be enabled with `ipv6 unicast-routing`.
* If IPv6 routing is disabled, the router will be able to send and receive IPv6 traffic, but will not *route* IPv6 traffic (=will not forward it between networks).

To demonstrate IPv6 routing commands, let's use the network below:

![Pasted image 20260704095601.png](../_assets/Pasted%20image%2020260704095601.png)

Here is R1's IPv6 routing table:

![ 500](../_assets/Pasted%20image%2020260704144032.png)

* Just like IPv4, a connected *network route* is automatically added for each connected network (`2001:db8:0:1::/64`).
* A local *host route* is automatically added for each address configured on the router (`2001:db8:0:1::1/128`).
* The `FF00::/8` via `Null0` route means discard all traffic matching this route, which as you noticed is the multicast address. This means discard all multicast traffic and it is automatically configured. It is beyond the scope for the CCNA.
* Routes for link-local addresses are not added to the routing table.

Here is the IPv6 static routing command:

![ 700](../_assets/Pasted%20image%2020260704144710.png)

* The `ipv6 route *destination/prefix-length*` part is easy to understand.
* The `{next-hop | exit-interface [netxt-hop]}` part is more tricky to understand. Curly brackets means a required choice. This means you have to either enter the next hop or the exit interface with optional next hop (square bracket means optional).
* `[ad]` means it is optional too. ad is simply **administrative distance** which you can use for floating static routes.

There is actually a name when configuring only exit-interface, only next hop, etc. when setting static routes. Note that it is not unique to IPv6 static routing (it also applies to IPv4).

* **Directly attached** static route: Only the exit interface is specified.
  `ipv6 route *destination/prefix-length* *exit-interface*`
  EXAMPLE: `R1(config)# ipv6 route 2001:db8:0:3::/64 g0/0`
  
  **NOTE:** In IPv6, you CAN'T use directly attached static routes if the interface is an **Ethernet interface**. This means the command `R1(config)# ipv6 route 2001:db8:0:3::/64 g0/0` actually won't work. The router *will* let you enter the command and become part of router's configuration. But it won't work and R1 won't simply send the packets.If it's a **Serial interface** however, it would work, but not on an Ethernet interface.

* **Recursive** static route: Only the next hop is specified.
  `ipv6 route *destination/prefix-length* *next-hop*`
  EXAMPLE: `R1(config)# ipv6 route 2001:db8:0:3::/64 2001:db8:0:12::2`
  
  Why is it called **recursive**? It's because it requires recursive lookup in the routing table. R1 has to look at its routing table multiple times. First, it has to look at its destination, then it has to look at the next hop to determine which interface to send the traffic out of.
  
  ![ 300](../_assets/Pasted%20image%2020260704150118.png)
  
  To demonstrate, to determine what interface to send out of to reach `2001:db8:0:3::/64`, R1 has to do lookup again to check which interface is `2001:db8:0:12::2` connected to (which is the next-hop). After doing lookup again, it can determine that `2001:db8:0:12::2` is part of R1's G0/0 interface.

* **Fully specified** static route: Both the exit interface and next hop are specified.
  `ipv6 route *destination/prefix-length* *exit-interface* *next-hop*`
  EXAMPLE: `R1(config)# ipv6 route 2001:db8:0:3::/64 g0/0 2001:db8:0:12::2`

**Here are some example commands when configuring static routes:**

![Pasted image 20260704152133.png](../_assets/Pasted%20image%2020260704152133.png)

**Network route:**

* `R1(config)# ipv6 route 2001:db8:0:3::/64 2001:db8:0:12::2` -> to reach `2001:db8:0:3::/64` subnet, R1 will have to reach R2's G0/0 interface.

**Host route:**

* `R2(config)# ipv6 route 2001:db8:0:1::100/128 2001:db8:0:12::1` -> to reach PC1. We also used /128 prefix length to be the most specific and to point to the actual end host.
* `R2(config)# ipv6 route 2001:db8:0:3::100/128 2001:db8:0:23::2` -> to reach PC2.

**Default route:**

* `R3(config)# ipv6 route ::/0 2001:db8:0:23::1`

Notice that the static routes we configured in the example are all **recursive static routes**, just to point out.

**Configuring floating static route:**

* Just like what we learned in dynamic routing, the same concept applies to IPv6 dynamic routing when configuring floating static routes.
* Always set the **Administrative Distance** of a static route to a value higher than default AD of dynamic routing protocol
* For example, if you use **OSPF**, set the **ad** value to more than 110 (**ad = >110**)
* If you use **EIGRP**, set the **ad** value to more than 90 (**ad = >90**)

### Link-Local Next Hops

![ 500](../_assets/Pasted%20image%2020260704152437.png)

Just like what we learned previously, if you want to use link-local address as the next hop when configuring static routes, you also have to include the **exit-interface**.

For example, the command `ipv6 route 2001:db8:0:3::/64 fe80::ef8:22ff:fee6:d300` won't work. You also have to include the exit interface, so the working command will be `ipv6 route 2001:db8:0:3::/64 g0/0 fe80::ef8:22ff:fee6:d300`.

Notice that to configure link-local next hops, you have to use **fully specified** static routes! Why we need to also include the exit-interface? **Because the router cannot find on its own which interface the link-local address belongs to even when doing recursive lookup**. Remember that link-local address are not included in IPv6 routing table by default.
