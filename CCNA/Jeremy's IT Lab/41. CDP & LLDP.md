### Layer 2 Discovery Protocols

![ 500](../_assets/Pasted%20image%2020260706210836.png)

* Layer 2 discovery protocols such as CDP and LLDP share information with and discover information about neighboring (connected) devices.
* The shared information includes host name, IP address, device type, etc.
* CDP is a Cisco proprietary protocol.
* LLDP is an industry standard protocol (IEEE 802.1AB).
* Because they share information about the devices in the network, they can be considered a security risk and are often not used. It is up to the network engineer/admin to decide if they want to use them in the network or not.

---

### Cisco Discovery Protocol

* CDP is a Cisco proprietary protocol.
* It is enabled on Cisco devices (routers, switches, firewalls, IP phones, etc) by default.
* CDP messages are periodically sent to multicast MAC address `0100.0CCC.CCCC`.
* When a device receives a CDP message, it processes and discards the message. It does **NOT** forward it to other devices.
* By default, CDP messages are sent once every **60 seconds**.
* By default, the CDP holdtime is **180 seconds**. If a message isn't received from a neighbor for 180 seconds, the neighbor is removed from the CDP neighbor table.
* CDPv2 messages are sent by default.
  - There are two versions of CDP: CDPv1 and CDPv2.
  - CDPv1 is very old and you don't need to know the difference between two versions except that CDPv2 is more advanced.

#### Basic CDP `show` commands

![ 500](../_assets/Pasted%20image%2020260706211743.png)

* **`show cdp`**: tells CDP timer (60 seconds by default), CDP holdtime (180 seconds by default), and which version of CDP is used (CDPv2 by default).
* The terminal will display `% CDP is not enabled` if CDP is disabled and you entered `show cdp`.

![ 500](../_assets/Pasted%20image%2020260706212009.png)

* **`show cdp traffic`**: tells how many CDP packets and CDP advertisements the device sent and received.

![ 500](../_assets/Pasted%20image%2020260706212242.png)

* **`show cdp interface`**: shows basic CDP information about interfaces such as the CDP timer, holdtime, and the encapsulation type (ARPA/Ethernet2 is a type of Ethernet encapsulation, which is beyond the scope of CCNA).
* At the end of interface information, it shows the number of CDP-enabled interfaces, how many interfaces are up and how many interfaces are down.

![ 500](../_assets/Pasted%20image%2020260706212726.png)

* **`show cdp neighbors`**: R1 learned R2 through G0/1 interface and learned SW1 through G0/0 interface. The command `show cdp neighbors` lets you see the learned neighbors of the Cisco device.
* This command shows the Device IDs of learned neighbors, the local interface they are connected to, holdtime timers (resets to 180 once it reaches 0), capabilities, platform, and port ID.
* The `Capability` column helps identify what kind of device you are connected. You can look at `Capability Codes` to check the individual letters in the column to determine the capabilities of the device. SW1 has capability of `R S I`, since it is a multilayer switch, it also has letter `R`.
* The `Platform` column displays the model of the neighboring device (for example `C2900` value for C2900 Series Cisco routers). If you use virtual devices such as GNS3, it will be blank since you are not using actual physical network devices with models.
* `Port ID` tells the port ID of the neighboring device. In this example, R1 is connected to SW1's G0/0 interface and R2's G0/0 interface.

![Pasted image 20260706215519.png](../_assets/Pasted%20image%2020260706215519.png)

* Another useful command is **`show cdp neighbors detail`** which displays more detailed information about the CDP neighbors based on device ID.
* One of the difference between CDP and LLDP is that it displays `VTP Management Domain`. VTP is Cisco proprietary so it is only available on Cisco devices. CDP is also Cisco proprietary.

![Pasted image 20260706215740.png](../_assets/Pasted%20image%2020260706215740.png)

* To view a specific neighbor, use **`show cdp entry *name*`**

### CDP Configuration Commands

* CDP is globally enabled by default.
* CDP is also enabled on each interface by default.
* To enable/disable CDP globally: **`R1(config)# [no] cdp run`**
* To enable/disable CDP on specific interfaces: **`R1(config)# [no] cdp enable`**
* Configure the CDP timer: **`R1(config)# cdp timer *seconds*`**
* Configure the CDP holdtime: **`R1(config)# cdp holdtime *seconds*`**
* Enable/disable CDPv2: **`R1(config)# [no] cdp advertise-v2`**

---

### Link Layer Discovery Protocol

* LLDP is an industry standard protocol (IEEE 802.1AB).
* It is usually disabled on cisco devices by default, so it must be manually enabled.
* A device can run CDP and LLDP at the same time.
* LLDP messages are periodically sent to multicast MAC address `0180.C200.000E`.
* When a device receives an LLDP message, it processes and discards the message. It does **NOT** forward it to other devices.
* By default, LLDP messages are sent once every **30 seconds**.
* By default, the LLDP holdtime is **120 seconds**.
* LLDP has an additional timer called the 'reinitialization delay'. If LLDP is enabled (globally or on an interface), this timer will delay the actual initialization of LLDP, which is **2 seconds** by default.

---

### LLDP Configuration

* LLDP is usually globally disabled by default.
* LLDP is also disabled on each interface by default.
* To enable LLDP globally: **`R1(config)# lldp run`**
* To enable LLDP transmission on specific interfaces (tx): **`R1(config)# lldp transmit`**, enables the interface to transmit LLDP messages. However, it won't receive LLDP messages (discards it)
* To enable LLDP in a receive direction (rx): **`R1(config)# lldp receive`**, this time it will receive LLDP messages.
* Configure the LLDP holdtime: **`R1(config)# lldp holdtime *seconds*`**
* Configure the LLDP reinitialization timer: **`R1(config)# lldp reinit *seconds*`**

### LLDP verfication (`show` commands)

![ 300](../_assets/Pasted%20image%2020260706222206.png)

Let's use the same network. This time, we enabled LLDP on all devices using `lldp run` from global config mode and also enable them on interfaces using `lldp transmit` and `lldp receive`. They are now running both CDP and LLDP.

![Pasted image 20260706222507.png](../_assets/Pasted%20image%2020260706222507.png)

* **`show lldp`**: gives the same information as `show cdp` does for CDP. Displays each of LLDP timers.

![Pasted image 20260706222446.png](../_assets/Pasted%20image%2020260706222446.png)

* **`show lldp traffic`**: how many frames does LLDP sent and received.

![ 200](../_assets/Pasted%20image%2020260706222711.png)

* **`show lldp interface`**: shows whether LLDP transmit and receive are enabled/disabled on each interface, as well as Tx and Rx state.

![ 500](../_assets/Pasted%20image%2020260706222915.png)

* **`show lldp neighbors`**: the output is almost the same as `show cdp neighbors`.
* It displays the Device IDs of neighbors, the local interface the device is connected to the neighbors, hold timers, Capability, and port ID (the neighbor's interface ID the local device is connected to).
* The difference between `show lldp neighbors` and `show cdp neighbors` is that in LLDP, it won't count down the `Hold time` values over time, and simply displays the whole time what is configured on the device.
* Another difference is that the Capability `S` meaning "switch" is gone, it is displayed as **Bridge** (`B`). Although SW1 is a switch, there is no `B` capability shown in `Capability column` in the output above, because we are running virtual devices in GNS3, and is not detecting that SW1 is an active switch. You should normally see `B` capability on real network devices.

![Pasted image 20260706224021.png](../_assets/Pasted%20image%2020260706224021.png)

* Here is the output of more detailed information on LLDP neighbors using **`show lldp neighbors detail`**.
* `Time remaining` actually counts down up to 0 so you have to use the detailed version of showing LLDP neighbors to see the holdtime counting down.
* It shows which system capabilities the device have and which is enabled. Since we didn't used `ip routing` command, the routing capability (`R`) is not showing on `Enabled Capabilities`. Since SW1 is a virtual device running in GNS3, the `B` (bridge) system capability is not showing for some reason.
* The `show lldp neighbors detail` doesn't show VTP information since VTP is Cisco proprietary.

![Pasted image 20260706224144.png](../_assets/Pasted%20image%2020260706224144.png)

* To view only specific entries, use the command **`show lldp entry *name*`**.
* This time, we enabled `ip routing` so `R` is showing in `enabled capabilities`.

### Wireshark Capture

Since CDP and LLDP both works at Layer 2, there are no IP packets to be shown in Wireshark.

#### CDP Packet Capture

![ 500](../_assets/Pasted%20image%2020260706225637.png)

* the holdtime is displayed as `TTL` in WireShark packet capture.
* no IP packet shown in Ethernet frame since CDP is strictly Layer 2 protocol.

**NOTE:** the multicast address `0100.0ccc.cccc` is not unique to CDP and is actually used by other protocols. You can see in Wireshark which protocols use this multicast MAC address (CDP, VTP, DTP, PAgP, UDLD)

#### LLDP Packet Capture

![ 500](../_assets/Pasted%20image%2020260706230307.png)

* the destination MAC address is the LLDP multicast MAC address (\`0180.c200.000e)
* Aside from `Time To Live` (the LLDP hold time), you can also see the `System Name`, which is the device who sent this message (in this case, SW1).
