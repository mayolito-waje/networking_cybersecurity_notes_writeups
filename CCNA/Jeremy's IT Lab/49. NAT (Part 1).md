### Private IPv4 Addresses (RFC 1918)

* IPv4 doesn't provide enough addresses for all devices that need an IP address in the modern world.
* The long-term solution is to switch to IPv6. But it is not an easy task to do so a short-term solution is also developed.
* The three main short-term solutions are:
  1. CIDR (Classless Inter-Domain Routing)
  2. Private IPv4 addresses
  3. NAT (Network Address Translation)
* **RFC 1918** specifies the following IPv4 address ranges as <u>private</u>:
  - **`10.0.0.0/8`** (`10.0.0.01` to `10.255.255.255`) --> range from Class A
  - **`172.16.0.0/12`** (`172.16.0.0` to `172.31.255.255`) --> range from Class B
  - **`192.168.0.0/16`** (`192.168.0.0` to `192.168.255.255`) --> range from Class C
* You are free to use these addresses in your networks. They don't have to be globally unique.
  ![Pasted image 20260720050023.png](../_assets/Pasted%20image%2020260720050023.png)
  \*==Private IP addresses cannot be used over the Internet!==

To demonstrate NAT, somewhere along the Internet, a PC have the same address and default gateway.

![Pasted image 20260720050236.png](../_assets/Pasted%20image%2020260720050236.png)

Without NAT, there are two problems:

1. Duplicate addresses
1. Private IP addresses can't be used over the Internet, so the PCs can't access the Internet.

![Pasted image 20260720050443.png](../_assets/Pasted%20image%2020260720050443.png)

* With NAT, there is an internal IP addresses but one external IP address from the router.
* The external IP address will be the one to be used to traverse over the Internet.
* This means that multiple devices can connect to the single gateway where each device have different \*<u>private IP address</u>, but share the single <u>external IP address</u> when connecting to the Internet.

### Network Address Translation (NAT)

![Pasted image 20260720051536.png](../_assets/Pasted%20image%2020260720051536.png)

* Network Address Translation (NAT) is used to modify the source and/or destination IP addresses of packets.
* There are various reasons to use NAT, but the most common reason is to allow hosts with private IP addresses to communicate with other hosts over the Internet.
* For the CCNA you have to understand **source NAT** and how to configure it on Cisco routers.

---

### Static NAT

![Pasted image 20260720051841.png](../_assets/Pasted%20image%2020260720051841.png)

* **Static NAT** involves statically configuring **one-to-one** mappings of private IP addresses to public IP addresses.

* An ***inside local*** IP address is mapped to an ***inside global*** IP address.
  - **Inside Local** = The IP address of the *inside* host, from the perspective of the local network
  \*the IP address actually configured on the inside host, usually a private address
  - **Inside Global** = The IP address of the *inside* host, from the perspective of *outside* hosts
  \*the IP address of the inside host <u>after NAT</u>, usually a public address
  - ![Pasted image 20260720052353.png](../_assets/Pasted%20image%2020260720052353.png)
  - In Static NAT, we don't use R1's interface IP, `100.0.0.1` is separate IP address reserved just for PC1.
  - ![Pasted image 20260720053135.png](../_assets/Pasted%20image%2020260720053135.png)
  - If PC2 wants to communicate to `8.8.8.8` (external server) using static NAT, ==it won't be allowed to use the same inside global address as PC1== (`100.0.0.1`). This is because static NAT is **one-to-one** mapping, PC2 will have its own inside global IP (`100.0.0.2`).

* ==**Static NAT** allows devices with private IP addresses to communicate over the Internet. However, because it requires a **one-to-one IP address mapping**, *it doesn't help to preserve IP addresses*.==

### Static NAT Configuration

![Pasted image 20260720054724.png](../_assets/Pasted%20image%2020260720054724.png)

* **NOTE:** ==to use inside global IP address for static NAT, you have to actually own these IP addresses because they are public IP addresses. These IP addresses must be registered to you or your company. You cannot freely use any public IP addresses you want.==
* After the static NAT configuration is done, if you look at **`show ip nat translations`**, you can see that the entries (Inside Global/Local) are *permanently displayed* in the translation table.
* Notice the configured IP addresses, they have numbers after colon (100.0.0.1:**56310**). These are **port numbers**. We will look at **Port Address Translation** (PAT) after this lesson.
* Also R1 doesn't translate port numbers using NAT for inside local/global and outside local/global, they are all the same after translation (only IP address is translated).

### Cisco NAT Terminology

![Pasted image 20260720063001.png](../_assets/Pasted%20image%2020260720063001.png)

* We learned about **Inside Local** and **Inside Global** earlier.
* We learn two new terms: **Outside Local** and **Outside Global**.
* **Outside Local** is the IP address of the *outside* host, from the perspective of the local network.
* **Outside Global** is the IP address of the *outside* host from the perspective of the outside network.
* Usually, the outside local and the outside global IP addresses are the same if destination NAT aren't used.

### `clear ip nat translation *`

![Pasted image 20260721052944.png](../_assets/Pasted%20image%2020260721052944.png)

* **`clear ip nat translation *`**: clear all **dynamic translations** in the NAT translation table.
* Although we only configured static NAT, each time static NAT entries are actually used, dynamic entries are added to the NAT translation table for those translations.
* When PC1 and PC2 stop communicating with `8.8.8.8`, dynamic entries will eventually be timed out and will be removed from the NAT translation table. `clear ip nat translation *` allows you to manually clear those dynamic entries (**not** the static NAT, those will persist forever unless you removed `ip nat inside source static...` from the router).

### `show ip nat statistics`

![Pasted image 20260721053833.png](../_assets/Pasted%20image%2020260721053833.png)

* Another useful command is **`show ip nat statistics`**. Let's walk through some of the entries.
* `Total active translations: 2` = since we cleared the dynamic entries, there are only 2 configured static NATs.
* `Peak translations: 4` = highest number of translations have been in R1's NAT table.
* `Outside interfaces/Inside interfaces` = which R1 interface is outside and which is inside.
