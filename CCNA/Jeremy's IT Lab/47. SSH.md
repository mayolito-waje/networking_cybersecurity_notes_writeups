### Console Port Security - `login`

* By default, no password is needed to access the CLI of a Cisco IOS device via the console port.
* You can configure a password on the *console line*.
  - A user will have to enter a password to access the CLI via the console port.

![Pasted image 20260718101138.png](../_assets/Pasted%20image%2020260718101138.png)

**To have a single console *line*** = there can only be a single console connection at once. You can't have multiple people configuring the same device at the same time via separate console ports. Only one user can connect at a time.

### Console Port Security - `login local`

* Alternatively, you can configure the console line to require users to login using one of the configured usernames on the device.

### Layer 2 Switch - Management IP

* Layer 2 switches don't perform packet routing and don't build a routing table. They aren't IP routing aware.
* However, you can assign an IP address to an SVI to allow remote connections to the CLI of the switch (using Telnet or SSH).

### Telnet

* Telnet (Teletype Network) is a protocol used to remotely access the CLI of a remote host.
* Telnet was developed in 1969.
* Telnet has been largely replaced by SSH, which is more secure.
* Telnet sends data in plain text. No encryption! This means you can easily capture sensitive packets (such as those containing passwords) using tools like Wireshark.
  ![Pasted image 20260718103442.png](../_assets/Pasted%20image%2020260718103442.png)

### SSH

* SSH (Secure Shell) was developed in 1995 to replace less secure protocols like Telnet.
  ![Pasted image 20260718132804.png](../_assets/Pasted%20image%2020260718132804.png)

* SSHv2, a major revision of SSHv1, was release in 2006.

* If a device supports both version 1 and version 2, it is said to run 'version 1.99'. This doesn't mean that it is lower version than 2, but rather that it supports both versions.

* Provides security features such as data encryption and authentication.
  ![Pasted image 20260718132936.png](../_assets/Pasted%20image%2020260718132936.png)
  
  Even if you can capture the packets, the contents will be encrypted because of SSH. Only client and server can decrypt it. SSH *server* (the device being connected to) listen for SSH traffic on **TCP port 22**.

* The keys are used for data encryption/decryption, authentication, etc.
