### The Purpose of DNS

* DNS is used to *resolve* human-readable names (google.com) to IP addresses.
* Machines such as PCs don't use names,they use addresses (ie. IPv4/IPv6).
* Names are much easier for us to use and remember than IP addresses.
  - What's the IP address of youtube.com?
* When you type 'youtube.com' into a web browser, your device will ask a DNS server for the IP address of youtube.com.
* The DNS server(s) your device uses can be manually configured or learned via DHCP.

### DNS Cache

![Pasted image 20260712173213.png](../_assets/Pasted%20image%2020260712173213.png)

* Devices will save the DNS server's responses to a local DNS cache. This means they don't have to query the server every single time they want to access a particular destination.
* **`ipconfig /displaydns`** = display the DNS cache.

![Pasted image 20260712173421.png](../_assets/Pasted%20image%2020260712173421.png)

* CNAME = **Canonical Name**
* CNAME is another type of DNS record maps a domain name to another domain name

![Pasted image 20260712173536.png](../_assets/Pasted%20image%2020260712173536.png)

* Here is the CNAME mapped to DNS A record which is the previous IPv4 address we saw mapped to youtube.com.

![Pasted image 20260712173751.png](../_assets/Pasted%20image%2020260712173751.png)

* **`ipconfig /flushdns`** = flush/remove the DNS cache.
* After flushing the DNS, nothing will be displayed when you enter the command `ipconfig /displaydns`.
* If you type `youtube.com` after flushing the DNS cache, PC1 will have to ask the DNS server (`8.8.8.8`) for the IPv4/IPv6 address of `youtube.com` again.

### Host File

![Pasted image 20260712173956.png](../_assets/Pasted%20image%2020260712173956.png)

* In addition to DNS cache, most devices have a 'host file' which contains a list of hosts and IP addresses.
* In Windows PCs, it is located in `C:/Windows/System32/drivers/etc/` directory and the file named `hosts` is the host file.

![Pasted image 20260712174228.png](../_assets/Pasted%20image%2020260712174228.png)

* We added a manual entry for IP address of R1, `ping` can successfully respond after typing `ping R1` because there is an entry in the host file.
* However, `ping R1` **doesn't use DNS**, and is simply an alternative to DNS with the use of host file.
* Before DNS was discovered, host files were used. DNS is a much better solution in modern networking and host files are only used for small scale of storing hosts and equivalent IP addresses.

### DNS in Cisco IOS

* For hosts in a network to sue DNS, you don't need to configure DNS on the routers. They will simply forward the DNS messages like any other packets.
* However, a Cisco router can be configured as a DNS server, although it's rare.
  - If an internal DNS server is used, usually it's a Windows or Linux server.
* A Cisco router can also be configured as a DNS client.

**DEMO 1:**

* We configured PC1 to use R1 as the DNS server instead of Google.
* **`ping <domain-name> -n <number-of-pings>`** - ping a domain/IP **n** times.
* PC1 doesn't have an entry in its own host table, so PC1 has to use DNS to learn the IP address of PC2.

![Pasted image 20260712181437.png](../_assets/Pasted%20image%2020260712181437.png)

* After PC1 learns PC2's address using DNS, it will store PC2's IP address in its own DNS cache.
* The next time PC1 **ping**s PC2, it won't have to ask R1 (DNS server) again because it already know PC2's IP address.

**DNS Demo 2**

Let's add another server accessible through Internet:

![Pasted image 20260712181640.png](../_assets/Pasted%20image%2020260712181640.png)

![Pasted image 20260712181822.png](../_assets/Pasted%20image%2020260712181822.png)

* Remember that we used the command `ip name-server 8.8.8.8` which serves as the DNS server for R1 if it doesn't have the entry in the host table for the requested record.
* R1 usually acts as the DNS server for PC1.
* But if R1 doesn't have an entry for the received DNS request, R1 will act as the DNS client and ask the Google DNS server for IP address of the requested hostname (`youtube.com`).
* After R1 knows the address of the unknown hostname (`172.217.25.110` for `youtube.com`), it will forward the learned information back to PC1 so PC1 can store the response results to its own DNS cache.

**`show hosts` command**

![Pasted image 20260712183033.png](../_assets/Pasted%20image%2020260712183033.png)

* **`show hosts`** - view both the configured hosts and also the hosts learned via the DNS.
* The cache entry for **youtube.com** that R1 learned via the Google DNS server is also added in the entry.
* The entry for youtube.com also have the flag `temp` in `Flags` category, meaning it is **temporary**, and R1 will have to relearn the entry if the entry expires.
* The manually configured entries are **permanent**, displayed as `perm` in the `Flags` category.

**Configuring Cisco Router as DNS Client**

We removed the host table, and reset R1 DNS server configuration.

* Two of the commands we learned are used to configure the Cisco IOS as the DNS client: **`ip name-server <address>`** and **`ip domain lookup`**.
* If PC1 pings R1 as a DNS server, R1 will not reply since it is not the DNS server anymore.
